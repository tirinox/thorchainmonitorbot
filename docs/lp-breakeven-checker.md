# THORChain LP Break‑even Checker — расширенное ТЗ

Статический мини‑вебапп: пользователь вводит любой адрес, видит все свои LP‑позиции в THORChain,
их текущую стоимость, причину просадки (синты / стрижка / замороженный пул / обычный IL),
точки безубыточности, график «стоимость позиции от цены RUNE и парного актива»
и кнопку «поделиться картинкой» для X/Twitter. Без бэкенда, без кошельков, без подписи транзакций.

Проверено на реальных данных 17.10.2026 (см. §10 «Контрольные кейсы»).

---

## 1. Принципы

1. **Истина — thornode.** Состояние пула и позиции берём только из thornode. Midgard нужен для
   списка позиций, истории действий и исторических цен. У Midgard по пулам с перекосом синтов
   битые числа (`units` и `synthUnits` отрицательные, `lpLuvi: NaN`) — ими не пользуемся.
2. **Повторяем формулы thornode буквально**, включая clamp знаменателя в synth units. Расчёт
   `share·R` и `share·A` обязан совпасть с `rune_redeem_value` / `asset_redeem_value` из thornode —
   это встроенная самопроверка.
3. **Только цифры и механика.** Никаких советов «держать/выходить». Все допущения модели
   написаны рядом с графиком.
4. **Приватность.** Адрес никуда не отправляется, кроме публичных нод. Картинка для шаринга
   по умолчанию маскирует адрес (`thor1j92…46na`).

## 4. Алгоритмы

### 4.1 Поиск позиций по адресу

1. Нормализовать ввод: trim; `thor1…` в нижний регистр; EVM‑адреса сравнивать без учёта регистра.
2. `GET /v2/member/{address}`. Принимает и RUNE‑адрес, и адрес актива любой сети.
   404 или пустой `pools[]` → «LP‑позиций не найдено» (savers и RUNEPool в v1 не ищем; показать
   ссылку‑подсказку, что это другие продукты).
3. Для каждого `pools[i]`: запомнить `runeAddress`, `assetAddress`, `liquidityUnits`, `*Added`, `*Withdrawn`,
   `*Pending`, `dateFirstAdded`.

### 4.2 Точное состояние позиции

**Ключ записи LP в thornode — RUNE‑адрес, если он есть.** Для симметричной позиции запрос
по адресу актива вернёт `units: 0` — это не «позиции нет», это неверный ключ.

```js
const lpKey = m.runeAddress || m.assetAddress;
const lp   = await thornode(`/thorchain/pool/${pool}/liquidity_provider/${lpKey}`);
const p    = await thornode(`/thorchain/pool/${pool}`);
```

Если `lp.units == 0 && pending == 0`, а Midgard показывает `liquidityUnits > 0` — расхождение
данных (Midgard отстал или позиция только что выведена): показывать предупреждение и верить thornode.

### 4.3 Доля в пуле и synth units (формулы thornode)

```js
function synthUnits(L, A, S) {           // все в базовых единицах 1e-8 (BigInt или Number с осторожностью)
  if (S === 0n || A === 0n) return 0n;
  let den = 2n * A - S;
  if (den <= 0n) den = 1n;               // clamp thornode: при S >= 2A synth_units = L·S, LP владеют ~0
  return L * S / den;
}
poolUnits = L + synthUnits(L, A, S);     // должно совпасть с pool.pool_units
share     = units / poolUnits;
redeemRune  = share * R;   redeemAsset = share * A;
assert(|redeemRune - lp.rune_redeem_value| < 1e-6 * R);   // самопроверка
V_now = redeemRune * P_rune + redeemAsset * P_asset;
```

Доля всех LP в пуле в закрытом виде (понадобится в модели):

```
f_pool = (2A − S) / (2A)   при 2A > S,   иначе ≈ 0
```

Использовать BigInt для `L·S` (в BTC‑пуле это 1e25, Number теряет точность); в Number
переходить только после деления.

### 4.4 Диагностика (что показать человеку словами)

Порядок проверок, первая сработавшая даёт основной бейдж, остальные — вторичные чипы:

| Код | Условие | Текст для пользователя |
|---|---|---|
| `PENDING` | `pending_rune > 0 || pending_asset > 0` | Незавершённый симметричный депозит: внесена одна сторона. |
| `SUSPENDED` | `status == 'Suspended'` | Пул приостановлен, вывод ограничен. |
| `FROZEN` | `status == 'Staged' || trading_halted` | Торговли нет → нет арбитража, состав позиции заморожен. Цена актива в thornode — из замороженного пула, не рыночная. Staged‑пул платит `StagedPoolCost` (10 RUNE) каждый `PoolCycle` (43 200 блоков ≈ 3 дня) из RUNE‑глубины. |
| `SYNTH_UNDERWATER` | `S >= 2A` | Пул «под водой» на `(S − 2A)/2` актива: синтов больше, чем пул может обеспечить. По формуле thornode LP владеют ~0. Восстанавливается только ростом A: ростом RUNE относительно актива или сокращением S. |
| `SYNTH_DILUTED` | `0.2 < S/(2A) < 1` | Синты забирают `S/(2A)` пула. |
| `HAIRCUT` | `luviGrowthPct < −0.15` и не объясняется синтами | Монеты из пула физически изъяты (пример: ADR‑028 после взлома 15.05.2026 — пулы без сейверов и POL, такие как BSC.TWT, BSC.USDT, BSC.USDC, были урезаны на 78–94 %). Цена этого не вернёт. |
| `HEALTHY` | иначе | Обычная позиция; просадка, если есть, — impermanent loss. |

`luvi_growth_pct` в thornode = `luvi_redeem / luvi_deposit − 1`. LUVI = `sqrt(R·A)/units_total`
не зависит от цены, поэтому растёт от комиссий и падает от стрижек и от синтов (через `pool_units`).
Для разделения «синты vs стрижка» считаем LUVI без синтов: `sqrt(R·A)/L`.

### 4.5 База депозита в USD

Midgard `actions` с типами `addLiquidity`, `withdraw` по адресу, фильтр по пулу
(`pools[0]` у действия). Для add суммы в `in[].coins`, для withdraw в `out[].coins`
(`liquidityUnits` в `metadata.withdraw` отрицательный).

Цена на дату действия:

```
depths = GET /v2/history/depths/{pool}?interval=day&from={ts}&count=1
assetUsd(t) = depths.assetPriceUSD
runeUsd(t)  = depths.assetPriceUSD / depths.assetPrice      // assetPrice = актив в RUNE
```

```
Deposit_USD = Σ_add (rune·runeUsd(t) + asset·assetUsd(t)) − Σ_withdraw (rune·runeUsd(t) + asset·assetUsd(t))
Coins_net   = (Σ runeAdded − Σ runeWithdrawn,  Σ assetAdded − Σ assetWithdrawn)
HODL_now    = Coins_net.rune · P_rune + Coins_net.asset · P_asset
```

Если `actions` недоступны — fallback на `rune_deposit_value`/`asset_deposit_value` из thornode
(это монеты, восстановленные по LUVI на момент депозита) и `dateFirstAdded` для цены. Пометить
как «оценка».

Кэш `history/depths` по `(pool, day)` в `localStorage`: цены за прошлые дни не меняются.

### 4.6 Декомпозиция потерь (водопад)

Показывает, **откуда** взялась разница между «держал бы монеты» и «есть сейчас». Все величины
при текущих ценах `p = P_rune`, `q = P_asset`; `r0, a0` — внесённые монеты (`Coins_net`
или `rune_deposit_value`, `asset_deposit_value`).

```
HODL        = r0·p + a0·q
IL_value    = 2·sqrt(r0·a0·p·q)                    // позиция в пуле при постоянном произведении, без комиссий
g           = (sqrt(R·A)/L) / (sqrt(r0·a0)/units)  // рост LUVI без синтов: комиссии (+) и стрижки (−)
V_nosynth   = IL_value · g                          // ≈ (units/L)·(R·p + A·q) — проверка
f_pool      = max(0, (2A − S)/(2A))
V_now       = V_nosynth · f_pool                    // ≈ share·(R·p + A·q) — проверка
```

Шаги водопада: `HODL → −IL → ±комиссии/стрижка (g) → −синты (f_pool) → V_now`.
Контроль на кейсе A (§10): HODL $7 882 → IL $3 235 → g ≈ 1.59 → $5 147 → f_pool ≈ 0 → $0.

### 4.7 Модель «что будет при другой цене»

Переменные `p` (цена RUNE, USD), `q` (цена актива, USD). Для арбитражной модели важно только `p/q`.

**Пул Available и торгуется** — арбитраж держит `R'·p = A'·q` при `k = R·A`:

```
A'(p,q) = sqrt(k·p/q)        R'(p,q) = sqrt(k·q/p)
f'      = max(0, (2A' − S)/(2A'))                  // S — слайдер, по умолчанию текущее
V(p,q)  = (units/L) · f' · (R'·p + A'·q) = (units/L) · max(0, 2A' − S) · q
```

**Пул FROZEN/Staged/Suspended** — арбитража нет, `R, A` фиксированы:

```
V(p,q) = share · (R·p + A·q)
```

Допущения, которые печатаются под графиком: `S` постоянен (слайдер меняет), комиссии и рост `k`
не учтены (они снижают пороги), для замороженного пула рыночная цена актива может отличаться
от `asset_tor_price` (поле ручного ввода `q`).

### 4.8 Точки безубыточности

Считаются при текущем `q` (и пересчитываются слайдером), выводятся как: цена RUNE в USD,
кратность к текущей, отношение RUNE/актив.

| Код | Смысл | Арбитражная модель | Замороженная модель |
|---|---|---|---|
| `T0` | позиция > 0 (только при `S > 0`) | `p0 = q·(S/2)²/k` | не применяется |
| `T1` | = HODL сейчас | `A' = (S + HODL/((units/L)·q))/2; p = q·A'²/k` | `p = (HODL − share·A·q)/(share·R)` |
| `T2` | = вложенные USD | то же с `Deposit_USD` | то же с `Deposit_USD` |
| `T3` | = стоимость без синтов | `V = (units/L)(R·p + A·q)` при `S = 0` → решить | — |

Если `p ≤ 0` или корня нет — «недостижимо ростом RUNE» (для замороженной модели сравнение с
HODL всегда проигрышное, если изъято > 0 % монет, — так и писать).

Для арбитражной модели у `T1` есть особенность: HODL сам зависит от `p`, поэтому решать
численно (бисекция по `p` на `[0.01·P_rune, 1000·P_rune]`, 60 итераций) — аналитическая форма
выше верна только при фиксированном целевом USD.

### 4.9 Асимметричные и частичные позиции

- Запись только с `asset_address` (без `rune_address`) — асимметричная позиция в активе;
  ключ — адрес актива; вывод возможен только с него.
- Запись только с `rune_address` без `asset_address` — RUNE‑асимметричная.
- `pending_*` > 0 — показать как отдельную карточку «ожидает вторую сторону», в стоимости не учитывать.

## 5. График и интерактив

- Chart.js 4 (UMD с cdnjs), одна y‑ось, одна серия, без радуги.
- Ось X: цена RUNE от `0.25·P_rune` до `15·P_rune`, переключатель лог/лин. Ось Y: USD.
- Пунктирные вертикали: «сейчас», `T0`, `T2`; горизонталь — `Deposit_USD`; подписи прямо на линиях.
- Слайдеры: цена актива `q` (×0.25…×4 от текущей), объём синтов `S` (0…100 %).
- Переключатель оси X: «от цены RUNE» / «от цены актива» (та же функция, фиксируется другой аргумент).
- Тултип: `p`, `V`, состав позиции в RUNE и активе, `A'`, `2A' − S`.
- Второй виджет — водопад из §4.6 (горизонтальные бары, 4 шага).
- Третий — мини‑спарклайн истории LUVI пула по неделям (`history/depths` → `sqrt(R·A)/units`),
  чтобы стрижка 26.08.2026 была видна глазами как обрыв.

## 6. Поделиться картинкой (X/Twitter и остальные)

### 6.1 Что на картинке

Формат 1200×675 (1.91:1, карточка X `summary_large_image`) и квадрат 1080×1080 для Telegram/IG.
Содержимое — одна «рунная плита» (см. §7):

- Название пула и логотип актива, бейдж диагностики (`Under water`, `Haircut`, `Frozen`, `Healthy`).
- Три крупных числа: «Сейчас», «Вложено», «Безубыток при RUNE = $X».
- Мини‑график `V(p)` с отмеченной текущей точкой и порогом.
- Маска адреса `thor1j92…46na` (переключатель «показать адрес»).
- Футер: дата, «данные: thornode via liquify», URL сайта. Без призывов, без прогнозов.

### 6.2 Как рендерить

Собственный `<canvas>` (без html2canvas — он плохо дружит с CDN‑шрифтами и `backdrop-filter`):

1. Рисуем фон, сетку, глифы из заранее подготовленных SVG‑path (инлайн), текст — шрифты через
   `document.fonts.load()` до рендера.
2. График переиспользуем: `chart.toBase64Image()` → `drawImage` на карточку.
3. `canvas.toBlob('image/png')` → объект `File`.

### 6.3 Как делиться

```js
const file = new File([blob], 'thorchain-lp.png', { type: 'image/png' });
if (navigator.canShare?.({ files: [file] })) {
  await navigator.share({ files: [file], text, url });          // мобильные: X, Telegram, iMessage напрямую
} else {
  downloadBlob(blob, 'thorchain-lp.png');                       // десктоп: скачать…
  window.open(`https://x.com/intent/post?text=${encodeURIComponent(text + ' ' + url)}`); // …и открыть пост, картинку вставить вручную
}
```

X intent не принимает файлы — на десктопе это «скачай + вставь», и это надо честно сказать
в UI («картинка скачана, вставьте её в пост»). Текст поста генерировать коротко:
`My BTC.BTC LP on THORChain: $0 now, breaks even at RUNE $5.06. Checked with <url>`.

### 6.4 Open Graph без бэкенда

Статика не умеет персональные OG‑превью. Два уровня:

- v1: общий OG‑image сайта; ссылка несёт адрес в хэше `#addr=…&pool=…`, страница по нему
  сразу открывает результат.
- v2 (опционально): Cloudflare Worker `/og?addr=&pool=` рендерит PNG тем же кодом карточки
  (satori + resvg‑wasm) и ставит `og:image`; тогда ссылка в X разворачивается в персональную карточку.
  Тот же Worker может быть CORS‑прокси к своей ноде.

## 7. Дизайн: техно × скандинавская мифология

THORChain уже говорит на этом языке: Asgard‑хранилища, Yggdrasil, Midgard, Mimir, Bifröst, Ragnarök
для удаления пула. Дизайн продолжает словарь, а не изобретает новый.

### 7.1 Настроение

«Рунный камень в серверной»: холодный ночной фон, зелёное свечение THORChain, гравировка рун,
тонкие технические линии, как в HUD. Не фэнтези‑иллюстрация, а знаки и геометрия.

### 7.2 Палитра

| Роль | Цвет | Примечание |
|---|---|---|
| Фон | `#0B1016` → `#121A24` | ночь, лёгкий вертикальный градиент |
| Плита (карточка) | `#161F2B` | камень, бордер `rgba(255,255,255,.08)` |
| Акцент THORChain | `#33FF99` | только для ключевых чисел и активного состояния |

| Текст | `#E8EDF2` / `#9AA7B4` / `#5F6E7C` | три уровня |
| Статусы | `#33FF99` healthy · `#F5B041` diluted · `#FF5C5C` under water / haircut · `#8FA3B8` frozen | всегда с иконкой и словом, не только цвет |

### 7.3 Типографика

- Заголовки и названия пулов: дисплейный шрифт с рунным характером — Cinzel (Google Fonts) или
  геометрический Space Grotesk с увеличенным трекингом; настоящие рунные шрифты только для декора.
- Цифры: JetBrains Mono / IBM Plex Mono, `font-variant-numeric: tabular-nums`.
- Текст: Inter.
- Единицы и валюты уменьшены на 70 % и подняты — как на приборе.

### 7.4 Символика состояний

| Состояние | Знак | Почему |
|---|---|---|
| Healthy | лист Иггдрасиля / руна ᛉ Algiz (защита) | пул жив, кормит |
| Synth under water | Ёрмунганд, кольцом обвивающий монету | змей, что обвил мир: синты обвили пул |
| Haircut | след укуса Фенрира на диске | монеты откушены |
| Frozen / Staged | Фимбульвинтер: иней на кромке карточки, руна ᛁ Isa (лёд) | торговля стоит |
| Pending | половина моста Биврёст | вторая сторона не пришла |
| Suspended / Ragnarök | треснувший камень | пул уходит |

Руны Старшего Футарка как орнамент: ᚦ Thurisaz (Тор) в логотипе, ᚱ Raido (путь/обмен) у графика,
ᚠ Fehu (богатство) у блока «Вложено». Каждая руна подписана в тултипе, чтобы не быть «просто закорючкой».

### 7.5 Движение

- Загрузка данных: молния пробегает по рамке карточки (как болты в swap‑картах бота), один раз.
- Ползунок цены двигает точку «сейчас» по кривой, кривая не перерисовывается с анимацией.
- Никаких бесконечных анимаций фона; `prefers-reduced-motion` отключает всё.

Варианты: **Mímisbrunnr** (источник Мимира — колодец, в котором видна правда), **Runestone**,
**Heimdall LP** (стражник, видит всё), **Breakeven Bifröst**. Домен проверить до выбора.

## 8. Интерфейс сайта

Одна страница, сверху вниз:

1. **Hero‑ввод.** Крупное поле «Вставьте адрес (thor1…, bc1…, 0x…)», кнопка‑молот. Под полем
   примеры‑чипы (три контрольных кейса из §10). Адрес и выбранный пул пишутся в `#hash`, ссылка шарится.
2. **Сводка.** Один ряд плиток: число позиций, суммарно «Сейчас / Вложено / HODL», худший бейдж.
3. **Карточки пулов («рунные плиты»)**, по одной на позицию, сворачиваемые:
   - шапка: логотип актива + бейдж диагностики + доля в пуле;
   - три числа: Сейчас / Вложено / HODL, под ними состав в монетах («178 RUNE + 182 TWT, 41 % и 14 % от внесённого»);
   - **водопад потерь** (§4.6) с подписями на русском/английском;
   - **таблица безубыточности** (§4.8) с кратностью к текущей цене;
   - **график** со слайдерами (§5) и строкой допущений;
   - аккордеон «Почему так» — текст диагностики с цифрами (`S = 517 BTC, 2A = 402 BTC`);
   - аккордеон «Как вывести» — мемо `-:{POOL}:10000`, напоминание, что ключ — RUNE‑адрес,
     MsgDeposit или MsgSend на модуль thorchain `thor1v8ppstuf6e3x0r4glqc68d5jqcs2tf38cg2q6y`;
   - строка «Источники» — сырые URL запросов;
   - кнопка **«Поделиться»** → превью карточки → «Скачать PNG» / «Поделиться» / «Открыть пост в X».
4. **Настройки** (шестерёнка): свой thornode/Midgard URL, язык RU/EN, валюта отображения USD/RUNE/актив,
   «показывать адрес на картинке».
5. **Футер**: допущения модели одним абзацем, «не финансовый совет», ссылка на исходники.

Пустые и ошибочные состояния: «позиций не найдено», «нода недоступна», «Midgard отстаёт от thornode
на N блоков» (из `/v2/health.lastAggregated.height` vs thornode `/thorchain/lastblock`).

Мобильный: карточка в одну колонку, график 16:10, слайдеры под ним, кнопка «Поделиться» прилипает снизу.

## 11. Риски и ограничения

- Liquify — единственный публичный хост с CORS; при его лимитах всё встаёт. Поле «своя нода» и
  Worker‑прокси — страховка.
- Midgard может отставать от thornode; сверять высоты и показывать предупреждение.
- Цена актива в замороженном пуле не рыночная; без внешнего прайс‑фида честно писать об этом.
- Модель арбитража — идеализация; реальные пороги ниже на величину накопленных комиссий.
- Дата‑зависимые события (ADR‑028, ThorFi) описывать как факты с датами, не как причину «навсегда».
